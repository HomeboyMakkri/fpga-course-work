## Установка после clone / git pull

В этом репозитории находятся все рабочие исходники MCP (`tools/altium`), настройка проекта (`.codex/config.toml`), навык (`.agents/skills/altium-library`) и результаты предыдущих проверок (`output/altium`). Отдельная установленная копия исходников не нужна.

На Windows нужны установленный Altium, Python 3.13 и Git. Из корня репозитория:

```powershell
.\tools\altium\setup.ps1 -AltiumExe 'Z:\Altium\X2.EXE' -RegisterUserMcp
```

`-RegisterUserMcp` обновляет только запись `altium_local` в пользовательской конфигурации Codex, сохраняя остальные настройки и резервную копию. Для работы только внутри доверенного проекта достаточно `.codex/config.toml`; глобальная регистрация необязательна. Если PowerShell запрещает запуск файлов, используйте `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\altium\setup.ps1 -RegisterUserMcp`.

`launch_mcp.py` автоматически создаёт локальную `.venv` при первом запуске через `setup.ps1` и устанавливает зависимости по `requirements.lock.txt`. Изменение этого файла после `git pull` запускает обновление зависимостей при следующем подключении MCP. Исходники и навык обновляются самим pull; уже запущенный MCP нужно переподключить. На первом запуске нужен интернет. Неверный путь Altium исправляется через `-AltiumExe` либо переменную `ALTIUM_EXE`; локальный `bridge_config.json` не попадает в Git. Python запускает MCP с прямой передачей stdin/stdout; PowerShell используется только для установки зависимостей.

Все журналы, резервные копии и личные настройки находятся в `tools/altium/runtime`, окружение — в `tools/altium/.venv`. Эти каталоги исключены из Git. Проверенные отчёты и библиотечные результаты публикуются в `output/altium`. `git pull` не устанавливает сам Altium, Python или шрифт GOST Common.

Проверка транспорта без редактирования CAD:

```powershell
.\tools\altium\.venv\Scripts\python.exe .\tools\altium\test_repo_transport.py
# Добавить --live для короткой проверки связи с уже открытым Altium.
```

## Что реализовано

- MCP stdio: реальная инициализация, список инструментов, вызовы проверены отдельным клиентом.
- Чтение сохранённых `.PrjPcb` и бинарных `.SchDoc`, включая компоненты, выводы, провода и метки.
- Запуск DelphiScript через штатный `ScriptingSystem:RunScript`, отдельный проект/результат для каждой команды.
- Создание листа по JSON с явными парами «вывод — сеть», чтение листа через SchServer, изменение параметра с резервной копией.
- `altium_compile_project`: компиляция указанного проекта, фактические сети выводов и Messages. При отсутствии physical-документов результат явно помечается `net_source=logical`; для многоуровневых проектов это не подтверждает межлистовую связность.
- Блокировка параллельных операций, журнал, тайм-аут, проверка доступности рабочего стола.

Результат запуска скрипта и электрическая проверка — разные проверки. Перед дальнейшими изменениями необходимо подтвердить работоспособность соответствующего инструмента на отдельном тестовом документе. Полный перенос PDF ещё не завершён.

## Подтверждённый результат 1 октября 2026

Открывайте `ARTIX/ARTIX/CodexGenerated/ARTIX_Codex_Verified.PrjPcb` и `Clock_Flash_Verified.SchDoc`. Перенесены QSPI W25Q128 и генератор 50 MHz со страницы 6 PDF: 8 компонентов, 24 вывода. Все 23 подключённых вывода совпали с JSON по сетям, прочитанным из **physical-документа собственного компилятора Altium**. Вывод X6.1 оставлен NC как в исходном PDF.

Через настоящий MCP stdio выполнены live health и компиляция; отчёт `mcp-transport-test.json` постоянной установки. Также выполнен реальный цикл изменения Comment → чтения → восстановления на первом тестовом листе; резервные копии находятся в `runtime/backups`. На итоговом листе Comment J2 восстановлен в `W25Q128JVSIQTR`.

`DM_Compile` возвращает False, Messages содержит замечания для одиночных выводов сетей, которые должны продолжаться к ещё отсутствующей FPGA, предупреждения по отсутствующим footprint и сетке. Успех проверки 23 сетей не означает чистый ERC. При дальнейшем переносе это нужно исправить, а не скрывать.

`Clock_Flash.SchDoc` и `ARTIX_Codex.PrjPcb` — ранние диагностические версии, их не используйте как исходник платы. Генератор исправлен после реальной компиляционной проверки: примитивы размещённого компонента имеют абсолютные координаты, библиотечные координаты сюда не подходят.

## Как работать в следующем чате

Для редактирования SchLib используйте постоянный навык `$altium-library` и новые команды `altium_inspect_library_component`, `altium_format_library_pins`, `altium_repartition_library_component`. Подробности, готовый запрос и сохранённая таблица FPGA: [LIBRARY_WORKFLOW.md](LIBRARY_WORKFLOW.md). Проверенный API и причины прежних сбоев сохранены в навыке. Изменения пинов выполняются над существующими библиотечными объектами с резервными копиями и проверкой после native save/reopen. Все три команды прошли реальный MCP-тест 2 октября 2026: 484 вывода, переход с двух частей на десять, изменение длины/шрифтов и проверка сохранности моделей; всего сервер предоставляет 12 инструментов.

Откройте Altium, затем новый чат Codex. Пример запроса:

> Используй altium_local. Проверь связь с Altium и прочитай проект ARTIX. Перед изменениями создай копию листа. Перенеси блок QSPI из PDF, проверь каждый вывод и сеть по сохранённому документу.

Сначала `altium_status(live=True)`. Для чтения сохранённого проекта — `altium_read_project`, для сохранённой схемы — `altium_read_saved_schematic`. Эти два инструмента работают без запущенного Altium. Они не отражают несохранённые изменения. Сети из файлового парсера не заменяют компиляцию проекта и ERC.

Для создания: `altium_create_schematic(manifest_path, output_path)` с новым именем `.SchDoc`. Перезапись существующего листа запрещена. JSON должен перечислять номера выводов и сети, источник, ограничения проверки; пример `manifests/clock_flash.json` — страница 6 PDF, QSPI и генератор 50 MHz. Это черновые символы без назначенных посадочных мест.

## Диагностика

### Исправления кода и внешние ограничения

Обычные ошибки кода/входных данных агент исправляет самостоятельно. На границах запуска скриптов, библиотечных операций и импорта пакетов MCP возвращает `CODE_REPAIR_REQUIRED` либо `EXTERNAL_CONSTRAINT_SUSPECTED`, факты, неопределённость и возможные следующие шаги. Сетевая ошибка не доказывает причину в VPN; ошибка CAD API не доказывает несовместимость версии. MCP не исправляет код сам и не создаёт диалог выбора: ответ интерпретирует агент согласно skills.

Пользователь нужен при ручном шаге, существенно новом пути либо зацикливании: три попытки без новых данных или десять минут без прогресса. Уже выбранный путь разрешает обычные исправления внутри него. Блокировка записей после неопределённого тайм-аута сохраняется; исправление кода не разрешает повтор частично исполненной записи без проверки состояния.

### Диагностика заданий и защита после тайм-аута

MCP теперь предоставляет 17 инструментов. Новые: `altium_diagnose_job`, `altium_recover_executor`, `altium_download_component_package`, `altium_prepare_component_package`, `altium_verify_component_original`. Текущему соединению MCP потребуется переподключение, чтобы увидеть новые инструменты; CLI использует обновлённые исходники сразу.

Каждое новое задание сохраняет `request.json` с исходным кодом и PID редактора вместе с `.pas`, `steps.txt` и `result.txt`. Диагностика читает эти файлы без CAD-вызова и различает отсутствие старта, выход редактора и незавершённое исполнение. Она не читает текст модального окна и не определяет несохранённые изменения. После неопределённого тайм-аута `runtime/blocked-job.json` запрещает следующие скрипты. После остановки ошибочного скрипта `altium_recover_executor` выполняет пятисекундную проверку связи; только точный успешный ответ снимает блокировку. Повтор записи автоматически не выполняется.

Preflight отклоняет подтверждённые опасные конструкции `raise Exception.Create`, `DoFileLoad` и `eSheetCustom` до запуска. Это не полноценный компилятор DelphiScript и не универсальное автоматическое исправление. Перед неподтверждёнными CAD API нужны отдельный тест и `LogStep` перед каждым существенным этапом.

```powershell
& .\tools\altium\.venv\Scripts\python.exe .\tools\altium\cad_bridge.py diagnose-job --path '<job_dir>'
& .\tools\altium\.venv\Scripts\python.exe .\tools\altium\cad_bridge.py recover-executor
```

### Скачанные компоненты: original / new

Пакет сохраняется в `ARTIX/ARTIX/libraries/<MPN>/original`, копия для редактирования — в `new`, происхождение и контрольные суммы — в `component.json`. Папка существующего элемента не перезаписывается. ZIP проверяется на выход за пределы папки и ограничения размера; HTML/PDF без CAD не принимаются как библиотека. Сохраняются вложенные пути и связанные файлы. Поле `COPIED_UNVERIFIED` означает только копирование, а не проверку распиновки или моделей. Форматирование/переразбиение через штатные библиотечные операции запрещено над `original` зарегистрированного пакета.

`altium_download_component_package` принимает известную прямую публичную HTTPS-ссылку. Сам инструмент не ищет компоненты, не управляет Manufacturer Part Search и не проходит авторизацию провайдера. Поиск, оценка пригодности, скачивание через браузер при необходимости и дальнейшая ГОСТ-адаптация описаны в `.agents/skills/altium-library/references/component-acquisition.md`.

```powershell
& .\tools\altium\.venv\Scripts\python.exe .\tools\altium\cad_bridge.py prepare-component --mpn '<MPN>' --manufacturer '<vendor>' --url '<source URL>' --path '<downloaded CAD ZIP>'
& .\tools\altium\.venv\Scripts\python.exe .\tools\altium\cad_bridge.py verify-original --path '<component folder>'
```

Для IntLib-only пакета требуется штатное извлечение исходников Altium в `new`. Копирование не исправляет абсолютные model links; их нужно проверить нативным чтением. Внешний вид должен проверяться отдельно; один шрифт не подтверждает полное соответствие ГОСТ. Текущие тесты новых функций проверяют импорт, контрольные суммы, отказ от небезопасных архивов, preflight и защиту восстановления; они не подтверждают живое восстановление Altium после падения.

PowerShell, если сервер ещё не появился в интерфейсе Codex:

```powershell
& ".\tools\altium\.venv\Scripts\python.exe" ".\tools\altium\cad_bridge.py" status --live
```

Результаты: `runtime/jobs/<id>/steps.txt`, `result.txt`, `.pas`, `.PrjScr`, общий `runtime/operations.jsonl`. Успешный ответ относится только к этой команде; старый файл не может выдать ложный успех.

`NOT_STARTED` означает, что Altium не начал нужный скрипт. `START` без `FINISHED` означает остановку внутри скрипта. При Error / `Another script executing now` закройте ошибку и остановите скрипт через Run → Stop. Если это не освобождает исполнитель, сохраните документы и перезапустите Altium обычным способом. Не повторяйте изменения вслепую. Пользовательский редактор принудительно не завершается.

Захват интерфейса Windows в этой сессии возвращал `window capture timed out`. Это отдельная проблема инструмента Computer Use, а не доказательство несовместимости Altium с MCP. Из-за неё текст некоторых ошибок требовал помощи пользователя.

## Временное отключение дополнений

4 октября 2026 по запросу пользователя восстановлен **только Library Loader**: `AltiumLL.vbs` совпадает по SHA256 с резервной копией, отключающий `Exit Sub` удалён. GOST BOM остаётся изолированным. Altium автоматически не перезапускался; активному редактору может потребоваться повторная загрузка скриптового проекта или обычный перезапуск после сохранения документов.

Для отдельного восстановления Loader: `tools/altium/.venv/Scripts/python.exe tools/altium/isolate_addons.py restore-loader`. Команда проверяет исходные контрольные суммы, сохраняет отключённый файл и не затрагивает другие дополнения.

По прямому запросу пользователя сохранены оригиналы GOST BOM и Library Loader в `addon-backup` постоянной установки. Регистрационный файл `GOSTBOM2.ins` переименован в `.ins.codex-disabled`; в процедуру `Prechecks` Library Loader вставлен `Exit Sub`. DLL, библиотеки и ГОСТ-шаблоны сохранены. Для чистого теста нужен обычный перезапуск Altium.

Восстановление:

Сначала сохраните документы и закройте Altium обычным способом.

```powershell
& ".\tools\altium\.venv\Scripts\python.exe" ".\tools\altium\isolate_addons.py" restore
```

Скрипт сверяет контрольные суммы резервных копий и откажется затирать Library Loader, если после отключения его изменили. После восстановления перезапустите Altium.

Причина сбоя пока не доказана: попытка `Client.StopServer('GOSTBOM2')` сама остановилась на ошибке. Она не используется для штатного отключения. Установленные дополнения не следует объявлять виновниками по одному совпадению.
